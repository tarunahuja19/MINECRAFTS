# B3 · FORGE right column: health strip, node card, mini map, FORGE alarms (+ live radius preview)

Built by Claude on 27 Sep (Antigravity's run had only started the 3D receiver).

## What changed

- **Right column** (`index.html` `#forge-right`, `css/sim-tab.css`, `js/sim/sim-tab.js`). Everything is coloured by the current FORGE frame's `node_states` from :8020, never by live or fixture states.
  - **Health strip:** `OK n · WARNING n · CRITICAL n`, then one 8 px dot per node. Clicking a dot selects that node.
  - **Node card:** id, role/tier, x/y, lat/lng, FORGE state, subsidence and tilt on the current FORGE day, nearest FORGE event, and the first WARNING/CRITICAL day. Shows "Click a node" when nothing is selected.
  - **Mini map:** an SVG of the 600 m site in engine metres (north up). It shows every node by FORGE state, each event as a circle of its radius labelled with its day, the target crosshair, and the dashed preview circle. Clicking a node selects it.
  - **FORGE alarms:** one line per node state change between frames, newest first ("Day 20.0 · N24 → CRITICAL (CAVE-IN #1, 52 m)"). RESET FORGE and LIVE DAY clear them. Nothing reaches the bus, the ALARMS tab or the banner.
- **Radius preview:** new embed command `forge-preview {x, y, radius_m}` (`sim-embed.js sendForgePreview`).
  - It is sent on every `input` of the active event's radius slider, on every terrain click, and when the event type changes.
  - `{x: null}` clears it; FIRE and RESET FORGE send that.
  - In the 3D view it moves the dashed beacon ring. `App.tsx` gained `beaconHidden` so the ring can be cleared.
- **PLAY no longer skips collapses.** Node states only change while a collapse is in progress (event day to collapse end + 0.05 d, about 0.6 d). At 20 d/s PLAY used to step straight over it, so PLAY now lands inside every such window once.
- **Frames carry `subsidence_mm` per node** (`simulation/forge/server.py`, vertical drop from `surface.channels` + cave-ins) for the node card.
- **The :8010 lab is gone from FORGE.**
  - `loadSegments`, `checkLabAvailability`, the snapshot/scenario fetches in `runScenario`, and the geology snapshot fetch in the sandbox pipeline are removed.
  - So are the SANDBOX CLUSTER NODES, SANDBOX SCENARIO ALARMS and SCENARIO CONSEQUENCE ANALYSIS panels and their dead code.
  - FIRE: CAVE-IN goes to the FORGE timeline. TILT and VIBRATION play their look at the target from the slider values, with no maths. CRACK says "NOT BUILT YET (B2d)".
  - `grep -n "LAB_API_BASE\|8010" sim-tab.js sim-embed.js` returns nothing.

## Deviations from the plan

- **The mini map is SVG in engine metres, not a second MapLibre map.** The plan said to reuse the MAP tab's projection. The node x/y in `fixtures/nodes.json` are the engine layout that the MAP lat/lng are projected from, so positions agree. The colours come from the same `nodeStateColor`.
- **"Nodes within 1.2R are CRITICAL" is checked at day 20.43, not at END.** Per the engine rule (`assign_node_states` on `active_collapses`), nodes return to ACTIVE once a collapse settles, so at END they are ACTIVE.

## Tests

- `verify_forge_close.js` now checks the FORGE node card instead of the removed clone list.
- `verify_sandbox.js` STEP 5: CRACK must no longer post lab `set-cracks`.
- `verify_sim_controls.js`: the pool now uses its own `TEST_DATABASE_URL`, because it failed without `PGPASSWORD` in the shell. The `mine_subsidence_test` database was created with `PGDATABASE=mine_subsidence_test node backend/db/migrate.js`.
- `acceptance_s3.js` is retired. Its checks were the gate banner (removed before B2b, failing since), the clone list, the sandbox notification feed and the :8010 health check, all removed on purpose. Its session and isolation checks live on in `verify_forge_close.js` and `verify_sandbox.js`.
