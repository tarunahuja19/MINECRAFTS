# E1 — shared event maths, lasting FORGE node states, strain cracks

## What changed
Python only; `session.assign_node_states` and `active_collapses` (the live engine's rule) are untouched — FORGE now keeps its own.

- New `simulation/sandbox/events.py`: `to_failures(ev: dict) -> list[PillarFailure]`, the one place a FORGE event turns into ground movement. `collapse_deltas` is linear in `magnitude_m` and translation-invariant, so tilt and crack solve their magnitude once at `magnitude_m = 1` on the settled state (`_SETTLED_DAY = 1000`) and divide, rather than iterating:
  - `cave_in`: one `PillarFailure`, as the live engine builds it today.
  - `tilt {x,y (target), radius_m, rate_mm_per_m, direction_deg, over_days, day}`: one failure centred a radius from the target along the bearing (`0° = N, 90° = E`), so the target sits on the bowl's flank. Its depth is solved (`_tilt_per_metre_of_depth`, `lru_cache`d by radius) so the settled tilt at the target equals `rate_mm_per_m`. Warning 1 h, duration = `over_days`.
  - `crack {x0,y0,x1,y1, throw_m, width_m, open_days, day}`: failures of radius `width_m` every `width_m/2` along the segment (ends included, `_crack_points`), one shared magnitude (`_throw_per_unit_magnitude`, `lru_cache`d by rounded length + width) so the settled `delta_s` at the midpoint equals `throw_m`. Warning 1 h, duration = `open_days`.
  - `normalise()` maps the legacy `{type:"cave_in", kind:"tilt", target_x, target_y, rate_mm_per_m, direction_deg}` shape onto a `tilt` event with `over_days = 3` — the old shape drew a cave-in one radius off target with depth `rate*R/1000`, which never actually delivered the requested rate.
  - `event_end_day(ev)`: day the event stops mattering to the timeline (settling + 5 days), used by `/forge/range`.
- `forge/server.py`: adds pydantic `TiltEvent` and `CrackEvent` to the `ForgeEvent` discriminated union. `forge_frame` now runs every event through `events.to_failures` (`failures_by_event`, kept per-event so states/zones/cracks can attribute damage back to its source) instead of only handling `CaveInEvent`. Node states come from `states.forge_node_states` instead of `assign_node_states(active_collapses(...))`. `/forge/range` sums `event_maths.event_end_day` instead of reimplementing the cave-in-only end-time formula.
- New `simulation/forge/states.py`:
  - `forge_node_states(nodes, events, failures_by_event, day, delta)`: only events with `day <= current day` count, and once counted they never stop (damage doesn't heal — the live engine's `active_collapses` was dropping a failure ~0.6 day after it started, which is why the FORGE health strip used to go green again over a still-open pit). Inside 1.2R of a started cave-in/crack (crack measured to the segment as a capsule) is CRITICAL, inside 1.5R is WARNING. Everywhere else, from the **event-induced delta only** (never the Knothe settlement bowl, which would otherwise redden the board with no operator input): WARNING if tensile strain ≥ `EPS_TENSILE_LIMIT` (5.3 mm/m), compressive ≥ `EPS_COMPRESS_LIMIT` (6.6 mm/m), or `|tilt| ≥ TILT_WARNING_MM_M` (3.0, new constant); CRITICAL if `|tilt| ≥ TILT_CRITICAL_MM_M` (10.0, new constant). Most severe reading wins; vibration changes no state.
  - `hazard_zones(...)`: `{event_index, kind, cx, cy | polyline, r_white=1.2R, r_red=1.5R}` for every started cave-in/crack.
  - `strain_cracks(...)`: a fixed 10 m lattice (`CRACK_LATTICE_M`) inside the window; wherever `max(strain_x, strain_y)` of the **total** field reaches the tensile limit, emits a segment centred on the cell (jittered by `zlib.crc32` of the cell index, so it's stable across calls — never flickers), perpendicular to the total tilt vector, length `4 + 2*(eps/limit)` m capped at 12, `width_mm = eps*1000`, `isNew = True` when the event's own delta supplies more than half the strain there. Capped at 400, strongest kept. User-drawn crack events add a jagged 6–10-segment polyline of their own (`_drawn_crack`, seeded by event index) on top.
  - Both constants `TILT_WARNING_MM_M = 3.0` and `TILT_CRITICAL_MM_M = 10.0` are marked ASSUMED (building-damage style limits) in `sandbox/constants.py`.
- Frame response adds `zones` and `cracks` alongside the existing `node_states`.
