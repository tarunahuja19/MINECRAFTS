# C4 — scripted demo runbook and QA checks

## What changed
- New `docs/DEMO-SCRIPTED.md`: a one-page runbook — start the stack (`npm start`), play the script (`npm run demo:scripted [-- --speed N]`), a day-by-day table of what the judges should see (day 60 crack, day 120 tilt, day 150 vibration, day 200 cave-in, with the exact timeline line each produces), how to open FORGE mid-run (seeds from the live day, fire an event of your own, what the rings/health strip/mini map should show), and troubleshooting (stale DB, `409` from `/script/run`, speed stuck at 10x).
- `scripts/qa.js` gains section 4, "FORGE isolation during a scripted run":
  - `checkNoForbiddenCalls()`: greps `simulation/forge/server.py` and `simulation/forge/states.py` for `/control`, `/api/simulation`, `:8010` or `/script/run` — FORGE must never name a write route (it may only read `:8000/interventions`).
  - `checkForgeIsolationDuringScript(spawnDemo)`: snapshots the live engine (`day, running, paused, speed, script, pillar_failures.length, alarm count`), drives every FORGE event kind through `POST :8020/forge/frame` at nine days (including one `include_grids: true` call) plus `/forge/range` and `/forge/seed`, then re-snapshots and asserts nothing on the live side moved except the day itself. Without `--scripted` it looks for a run already in progress and WARNs (doesn't fail) if none is found; with `--scripted` it spawns `run_scripted_demo.js --speed 0.4` itself and waits for it to reach day > 1.
  - Also fixes a stale assertion in the existing "sim-tab loading + lit-up" check: it looked for the literal string `'sim-live-lit'` in `sim-tab.js`, which the FORGE work had already renamed to `'forge-live-lit'`; the check now looks for the string that's actually there.
