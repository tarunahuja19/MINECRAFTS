# E2 — FORGE tilt creep and user-drawn cracks

## What changed
- **TILT** fires `{type:"tilt", x, y (target), radius_m, rate_mm_per_m, direction_deg, over_days, day}`. New OVER slider `sim-tilt-over` (1–30 d, default 3). The preview ring still sits on the offset bowl centre.
- **CRACK** sliders THROW (`sim-crack-throw` 0.05–2 m, 0.4), WIDTH (`sim-crack-width` 2–30 m, 8), OPEN OVER (`sim-crack-open` 0.5–30 d, 2).
  DRAW CRACK toggle: the next two `terrain-target` clicks set A and B (then drawing turns off, and the target is not moved). ESC or a second click cancels.
  Readout `A: x, y  B: x, y  length N m`. FIRE is disabled until B is set. Fires `{type:"crack", x0,y0,x1,y1, throw_m, width_m, open_days, day}`, then clears A/B.
- Preview: `forge-preview` embed command takes an optional `line`; the 3D view draws it as a dashed amber line on the base ground (`PreviewLineOverlay`); the SVG mini map draws it too.
- Event list: `Day 12.0 · CRACK 180 m, throw 0.40 m`, `Day 5.0 · TILT 5 mm/m → 90°, over 3 d`.
- Alarm "why" text and the node card's "Nearest event" use the nearest event of any kind (crack distance = to the segment).

## Notes
- TILT node state follows the tilt thresholds (WARNING ≥ 3 mm/m, CRITICAL ≥ 10), not the cave-in 1.2R rule: a 5 mm/m tilt turns the target node WARNING.
- ESC is heard on the dashboard document. After each terrain click `sim-tab.js` calls `window.focus()` so focus returns from the iframe; if the user orbits the view (drag) and then presses ESC, the click on DRAW CRACK is the fallback.
- The mini map is still the SVG (M1 replaces it), so A/B cannot be clicked there yet.
