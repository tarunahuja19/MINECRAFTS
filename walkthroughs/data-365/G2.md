# G2 — the district ground wired into the engine, FORGE and the frontend

## What changed
This step started with substantial uncommitted work already in the working
tree from a paused run (see `docs/plans/prompts/data-365-wip/G2-*-partial.*`
for the earlier draft). Rather than re-writing, each file was read in full
and checked against the plan's G2 bullet line by line; the work already
matched the brief, so this step is a verification pass plus the walkthrough
and commit, not a rewrite.

- **`simulation/sandbox/ground.py`** (new) is the single resolver both
  engines call through: `resolve(name)` maps `"district"`/`"surface"` to the
  `district`/`surface` modules (raising on anything else, never silently
  falling back), and `wire_fields()`/`static_bowl_fields()` are the one
  place that translates between `district`'s 3-panel wire shape
  (`bowl_terms_px`/`bowl_terms_py`/`face_positions`) and `surface`'s
  single-panel shape (`bowl_px`/`bowl_py`/`face_y_m`) — so `session.py` and
  `forge/server.py` can never resolve the same ground name to different
  code, or grow two independent copies of this branch.
- **`session.py`**: `SessionConfig.ground` defaults to `"district"`.
  `_resolve_ground()` (called from `__init__` and `_reset_state()`) picks
  the module and freezes its day-0 channels into `self._install_ch`. Every
  tick now samples sensors against `total_channels - self._install_ch`
  ("since install on day 0") rather than the absolute field — the zone
  manager still gets the absolute `total_channels`, only the sensor array's
  `truth_channels` argument changed. The tick payload's bowl/face fields
  come from `ground.wire_fields(self._ground, t_sim_days)` instead of a
  hard-coded `surface.bowl_py_wire`/`surface.face_y` pair.
- **`sandbox/server.py`**: `/config` and the WS `init` frame both get their
  `base_bowl_mesh`/`bowl_px`/`bowl_terms_px` from
  `ground.static_bowl_fields(session._ground)` instead of reading
  `surface._BASE_S`/`surface.bowl_px_wire()` directly.
- **`forge/server.py`**: `ForgeFrameRequest` gets a `ground: str = "district"`
  field so a single request can still pin `"surface"` for a test. Sensor
  sampling subtracts a per-ground-module cache of day-0 channels
  (`_get_install_ch`, keyed by module object) the same way `session.py`
  does, and the frame's bowl/face fields come from `ground.wire_fields`.
- **Old tests preserved on `surface`.** `test_bowl_profile.py`'s two tests
  that pin exact single-panel numbers now flip the shared session's
  `config.ground` to `"surface"` (via `_resolve_ground()`) for the duration
  of the test, restoring it in a `finally`. `test_forge.py`'s four tests
  that assert exact `surface.bowl_px_wire()`/`surface.face_y()` values now
  pass `"ground": "surface"` explicitly in the request body. Every other
  `/forge/frame` call in that file only asserts structure or relative
  deltas, so it needed no change and correctly now runs against the
  default `district` ground.
- **Frontend** (`types.ts`, `embed.ts`, `App.tsx`,
  `utils/geomechanicsEngine.ts`, `MineViewport.tsx`, `TerrainMesh.tsx`):
  `InitPayload`/`TickPayload`/`EmbedParentCommand` grow optional
  `bowl_terms_px`/`bowl_terms_py`/`face_positions` fields alongside the
  existing `bowl_px`/`bowl_py`/`face_y_m`. `LiveGeomechanicsEngine` gets
  `setBowlTermsPx`/`setBowlTermsPy`; its ground-sampling loop
  (`utils/geomechanicsEngine.ts` around the old line 631) sums all *n*
  panels — `totalDropM += sampleProfile(bowlTermsPx[k], x) *
  sampleProfile(bowlTermsPy[k], y)` for `k` in `0..min(len(px), len(py))`
  — and only falls back to the single `bowlPx * bowlPy` product in an
  `else if` when `bowlTermsPx`/`bowlTermsPy` are both absent (an older
  server, or a `"surface"`-ground response). `App.tsx`'s `applyBowl()` now
  takes the extra `termsPy`/`faces` arguments and threads them into both
  `globalGeomechanics` and component state; `MineViewport.tsx` /
  `TerrainMesh.tsx` just carry `bowlTermsPy` through as a prop so their
  `groundTick`/effect-dependency signatures change (and therefore redraw)
  when any of the 3 panel profiles move — the actual sampling stays inside
  `globalGeomechanics`, matching how `bowlPy` already worked.

No bugs were found in the ground-wiring code itself. Two files the plan
lists as touched, `backend/alarm/thresholds.js` (a `limitFor()` addition —
A1 scope) and `simulation/sandbox/environment.py` /
`simulation/tests/test_environment.py` (E1, new/untracked), are unrelated
leftover work from other steps sitting in the same working tree; they are
left alone and not part of this commit.

## Files
- `simulation/sandbox/ground.py` (new) — the `resolve()`/`wire_fields()`/
  `static_bowl_fields()` dispatcher between `district` and `surface`.
- `simulation/sandbox/session.py` — `SessionConfig.ground` (default
  `"district"`), `_resolve_ground()`, since-install sensor sampling, tick
  payload via `ground.wire_fields`.
- `simulation/sandbox/server.py` — `/config` and WS `init` bowl fields via
  `ground.static_bowl_fields`.
- `simulation/forge/server.py` — `ForgeFrameRequest.ground`, per-module
  install-channel cache, since-install sensor sampling, frame payload via
  `ground.wire_fields`.
- `simulation/tests/test_ground_wiring.py` (new) — 5 tests: default ground
  is `district`, tick carries 3×121 `bowl_terms_py`/`face_positions`,
  since-install channels are exactly zero at t=0 (both the raw channel
  arithmetic and telemetry sampled from it), `/forge/frame` carries the
  same 3-panel fields, `/config` carries 3×121 `bowl_terms_px`.
- `simulation/tests/test_bowl_profile.py` — the two exact-single-panel-value
  tests now pin `ground="surface"` on the shared session for their
  duration.
- `simulation/tests/test_forge.py` — the four exact-single-panel-value
  `/forge/frame` calls now pass `"ground": "surface"`.
- `simulation/frontend/src/types.ts`, `embed.ts`, `App.tsx`,
  `utils/geomechanicsEngine.ts`, `components/MineViewport.tsx`,
  `components/TerrainMesh.tsx` — the 3-panel wire fields end to end, with
  the single-panel path kept as a fallback.
- `walkthroughs/data-365/G2.md` (this file).
