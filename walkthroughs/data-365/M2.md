# M2 — sensors stop fabricating and start reading the environment

## What changed
`sandbox/sensors.py`'s corruption chain fabricated three of its channels
and invented a noise magnitude with no budget behind it. Each is now a
sourced, honest computation.

- **OU wander scaled to its named budget, per-second (not per-tick).**
  The strain wander (`node.wander_strain`) decayed at a fixed `phi=0.88`
  per call, which silently assumed every call was `TICK_SIM_SECONDS`
  (60 s) apart — true for the interactive tick, false for a scripted run's
  3600 s ticks, where the same fixed decay overstated the wander's
  real-world persistence 60x. Measured stationary std was ~9.5 µε against
  the sensor's own 1.332 µε noise budget (`SIGMA_STRAIN_UE`), a 7x
  overshoot. `_ou_step()` (new) re-discretizes a zero-mean OU process for
  any `dt_seconds`, anchored so it reproduces the historical `phi=0.88` at
  exactly the historical 60 s reference (`WANDER_PHI_PER_TICK`, new
  constant) — a continuous-time correlation constant derived once, not a
  second hand-typed number. Strain wander now targets `SIGMA_STRAIN_UE`
  directly; tilt wander targets each node's own `sigma_tilt_urad` (120 µrad
  MPU-6050, 3 µrad ADXL355 on Tier 2A) instead of an unbudgeted 18/3 µrad
  step; vibration and battery wander keep their own small ASSUMED budgets
  but are re-discretized the same way for dt-independence.
- **PPV kept separate from RMS, and attenuates with distance.** A live
  transient (`Session.apply_vibration`) used to add its flat `magnitude_ppv`
  into every node's RMS channel uniformly, regardless of position — the
  plan's "no node attenuates with distance" defect, and a transient PEAK
  value being summed into a continuous RMS reading. `magnitude_ppv` is now
  the PPV at `VIBRATION_REFERENCE_DISTANCE_M` (100 m, ASSUMED) from an
  optional source location (panel-centre by default — no existing caller
  passes a location, so this is additive, not breaking); each node's own
  PPV attenuates from that reference by the USBM exponent
  (`BLAST_USBM_BETA`, 1.6, already defined in E1's `environment.py`, VERIFY)
  over its own distance. The RMS channel is now baseline machinery noise
  only; the transient instead lifts the PEAK channel (`max(baseline peak,
  node PPV)`), matching what a real accelerometer reports — RMS of the
  ambient floor, a separate peak during an event.
- **Principal strain from strain_x AND strain_y**, not strain_x alone. This
  reduced engine has no shear cross-term, so with the district/surface
  axes already aligned to along/across-strike, the larger signed value IS
  the major principal strain; the old code silently missed every node
  where the across-strike (`strain_y`) component was the more tensile one.
  Applied to `strain_ue`, `fissure_mm`, and `ext_delta_10um`.
- **Fissure = the finale's `opening_mm`, latched.** Replaced the
  undocumented `max(0, strain_x) * 1000.0 * 2.0` (a bare, unstated 2 m
  gauge spacing, no threshold at all) with the exact relation
  `sih-26-finale/mine-sim/src/minesim/cracks.py::opening_mm` uses on
  principal tensile strain: `(e1_ue - threshold_ue) * 1e-6 * spacing_m *
  1000`, with `CRACK_TENSILE_THRESHOLD_UE` (3000 µε) and `CRACK_SPACING_M`
  (8 m) pulled verbatim from the finale's own `assumptions.yaml` (both
  still marked `OPEN — VERIFY` there). A crack opens only in tension and
  does not fully heal: `NodePersonality.max_fissure_mm` (new field) latches
  the largest width ever seen, and the reported width floors at
  `CRACK_PARTIAL_CLOSURE_FRACTION` (0.35, same source) of that max once
  latched — the ground can go back into compression and the crack narrows,
  but never below that floor and never to zero.
- **Pore pressure and moisture from the E1 environment, not a function of
  S.** Both were invented linear functions of subsidence depth
  (`180 - S*45` kPa, `12 + S*9` %) — physically backwards (moisture
  responds to rainfall infiltration, pore pressure to the aquifer's own
  recharge/drainage, neither directly to how deep the ground above has
  sunk). `sample_tick` gains an `environment_channels` parameter: this
  tick's per-node `pore_pressure_kpa`/`moisture_pct` arrays, in the same
  node order as `SensorArray.nodes` (`NodePersonality.array_idx`, new
  field). `SimulationSession._resolve_ground()` now also builds
  `self._environment = environment.build_year(self.config.seed)`, and
  `tick()` slices it by the current hour (clamped, not wrapped, past
  day 365) before passing it through. A caller with no environment
  attached (bare-kernel tests, the two other direct `sample_tick` callers)
  falls back to E1's own day-0 baseline constants
  (`PORE_PRESSURE_BASE_KPA`, `MOISTURE_BASE_PCT`) — never to a function of
  S.
- **Thermal tilt drift, 5 µrad/°C (VERIFY).** A MEMS package's own thermal
  expansion biases its zero point against a 25 °C calibration reference
  (`TILT_DRIFT_REFERENCE_C`, ASSUMED), independent of and additive to the
  ground's own tilt. Applied equally to both tilt axes — no per-axis
  thermal model is specified in the plan. This is a real, deterministic
  bias (not noise), so it now shows up even with `enable_noise=False` and
  even where the ground has moved exactly zero — `test_ground_wiring.py`'s
  `test_total_minus_install_equals_zero_at_t0` (G2) updated to compute the
  expected per-node drift instead of asserting a bare zero, since a zeroed
  *ground* reading and a zero *sensor* reading are no longer the same
  claim.

## Files
- `simulation/sandbox/sensors.py` — `_ou_step`, principal strain, fissure
  latching, distance-attenuated PPV separate from RMS, environment-sourced
  pore pressure/moisture, thermal tilt drift; `NodePersonality` gains
  `array_idx` and `max_fissure_mm`; `sample_tick` gains `dt_seconds`,
  `vibration_source_xy`, `environment_channels`.
- `simulation/sandbox/constants.py` — `CRACK_TENSILE_THRESHOLD_UE`,
  `CRACK_SPACING_M`, `CRACK_PARTIAL_CLOSURE_FRACTION`,
  `THERMAL_TILT_DRIFT_URAD_PER_C`, `TILT_DRIFT_REFERENCE_C`,
  `VIBRATION_REFERENCE_DISTANCE_M`, `WANDER_PHI_PER_TICK`.
- `simulation/sandbox/session.py` — `_resolve_ground()` builds
  `self._environment`; `tick()` slices it by hour and threads
  `dt_seconds`/`environment_channels` into `sample_tick`.
- `simulation/tests/test_sensor_honesty.py` (new) — 12 tests: OU wander
  std within 10% of budget and independent of tick length, PPV at
  100 m/30 kg against the USBM kernel and attenuating with node distance,
  RMS excluding PPV, fissure latch/floor/formula, principal strain,
  pore-pressure/moisture from environment vs. the E1 baseline fallback,
  thermal drift.
- `simulation/tests/test_ground_wiring.py` — updated
  `test_total_minus_install_equals_zero_at_t0` for the thermal drift term.
