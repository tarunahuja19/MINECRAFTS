## Prompt 2 — sitting B: wire.py + geo.py (the sign-flip and the map-maker)

```
Sitting B. Two new modules, each with a gate that fails if someone removes it.

### B1 — scenario-lab/lab/wire.py: the single serialisation boundary

Everything the lab ever sends out (REST today, files tomorrow) passes through wire.py.
It takes the raw dict from lab.consequence.evaluate() plus the Snapshot/Zone/EventResult
context, and returns PLAIN JSON-safe types only (no numpy scalars, arrays become lists):

- Flip signed vertical-displacement fields from positive-down (lab convention) to
  NEGATIVE-DOWN (wire convention) EXACTLY ONCE. Fields to flip: any subsidence/sinking
  mm value (e.g. summary.max_extra_sinking_mm). Fields to LEAVE: crack widths
  (magnitudes, >= 0), PPV, tilt/strain magnitudes, counts, bearings, epochs.
- Stamp every payload: kind ("scenario"), schema_version, run_id, mine, frozen_day,
  zone/segment id, event name, params_used, and label "SCENARIO (HYPOTHETICAL)".
- Crack segments keep the shape consequence.py already emits
  (x0_m/y0_m/x1_m/y1_m/bearing_deg/width_mm/new); wire only converts types and flips
  the sign of signed fields — it never recomputes.

### B2 — scenario-lab/lab/geo.py: our one metres<->lat/lon module

  advance_direction_deg (0 = east), +y = toward tailgate. Equirectangular projection

## Prompt 3 — sitting C: server.py + store.py (P3, the critical path)

```
Sitting C, on top of the B commit. The server the window will talk to.

### C1 — scenario-lab/lab/server.py (stdlib only — no new dependency)

ThreadingHTTPServer on lab.port (8010, already in config/lab.yaml). No fastapi, no pip
installs: pyproject stays numpy+pyyaml. Serves:
- renderer/ at / (static; Window 2 will need the same origin later).
- GET /api/run?run=<dir> — mine, run_id, days, face position today, node/tier counts.
- GET /api/segments — the 10 zones + full, with lat/lon bounds from lab/geo.py.
- GET /api/events — built from config/events/*.yaml via lab.config.load_event_spec
  (inputs with default/min/max/unit; a new event needs no page change).
- GET /api/objects — the illustrative village from lab/objects.py, with lat/lon.
- GET /api/snapshot?day=&segment= — block-averaged subsidence (display_cell_m) for the map.
- POST /api/scenario {day, segment|bounds, type, params} — the pipeline
  load_snapshot -> zone_by_id -> EVENTS[type] -> confine_to_zone -> (+ caving PPV) ->
  evaluate -> wire. Returns the wire JSON AND saves it via store.py.
  A refusal returns HTTP 200 with possible:false and the sentence — never an error.
- GET /api/scenarios, GET /api/scenarios/{id} — saved results.
- GET /health and POST /control in the old Box-2 shape
  ({is_running, is_paused, state, t_sim_seconds} / {action}) — drop-in for their dashboard.
- The run directory comes from a --run CLI flag, default ../mine-sim/out/v2-690d.

Two hard rules: NEVER derive tilt/strain from snap.s_mm (int-mm rounding gives strain
errors larger than the true peak — use s_model_mm via evaluate as what_if.py does);
NEVER write outside scenario-lab/store/.

### C2 — scenario-lab/lab/store.py

Saved scenario results under LabConfig.store_dir only. scenario_id = sha256 of the
canonical request JSON, first lab.id_hash_chars chars. Re-saving the same request
returns the same id (this is what makes L2 meaningful).

### Gates L1, L2, L3, L7 (scenario-lab/tests/gates/test_l1.py, test_l2_l3_l7.py)

- L1: hash every file of a REAL run dir before and after running EVERY scenario type
  (all of EVENTS) — byte-identical. Use a temp copy? NO — hash the real
  ../mine-sim/out/v2-690d in place; the point is the server cannot write there.
- L2: POST the same scenario twice -> byte-identical response bodies.
- L3: (a) AST scan over lab/**/*.py forbidding OUTBOUND client imports —
  requests, httpx, urllib.request, socket. http.server and urllib.parse are INBOUND/
  parsing and explicitly allowed; name them as allowed in the test docstring so a
  future reader does not "fix" it. (b) every path the server writes resolves inside
  store_dir.
- L7: every POST /api/scenario response contains label "SCENARIO (HYPOTHETICAL)".

### Verify before you stop

  cd scenario-lab && /opt/miniconda3/envs/pinn-sandbox/bin/python3.11 -m pytest -q
