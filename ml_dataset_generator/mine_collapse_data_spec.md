## 1. Project Context (read this first)

We are building a system to predict the risk of ground collapse in mines using a network of physical sensor nodes deployed underground. This document specifies **exactly** what data must be generated by MATLAB simulation, in what format, and how it will be used downstream. It is meant to be read with zero additional context — everything needed to build the simulation is contained here.

The end goal is **not** binary classification ("will it collapse: yes/no"). The goal is a **time-to-event / survival-analysis** model: for every sensor node, at every point in time, the model should be able to estimate a hazard curve — the probability that collapse has *not yet* occurred by some future time `t`, for any `t` the user queries. This changes what the *labels* must look like (see Section 5) — this is not a simple classification label set.

The trained model architecture (for context on how this data will be consumed, not something this document asks you to build) is:
- A **State-Space Model (Mamba-style SSM)** that encodes each node's own time series.
- A **spatiotemporal Graph Neural Network (GNN)** that passes messages between nodes based on their spatial layout, since node positions differ between mines and are not a fixed grid.
- Combined, these produce a per-node, per-timestep hazard estimate.

Because node placement differs across real deployments, the simulation must produce **many structurally different mines**, not one mine simulated many times. This is explained fully in Section 3.

> ### ⚠️ The architecture is exactly these two parts — there is NO PINN
>
> **SSM + GNN, nothing else.** No physics-informed network, no physics loss, no
> auxiliary physics objective. Anything describing a PINN for this project comes
> from a superseded design and does not apply.
>
> **Consequence for this dataset:** the clean `truth_*` columns are **debug-only**.
> With no physics loss they are never a training target, and feeding them to the
> model as inputs would leak the answer. Their sole purpose is answering *"is the
> data wrong or is the model wrong?"* when training misbehaves — which matters
> because survival labels cannot be eyeballed for correctness.

> ### Source authority for this document
>
> The only valid sources for this work are the three files in this folder:
> the **tier/sensor image** (hardware), **`mesh-communication-mechanics.md`**
> (network), and **this file** (objective, labels, output). Do not import facts
> from other folders in this repository — they describe superseded designs
> (a 7-sensor node, a geophone, a PINN) and will reintroduce contradictions.

## 2. Six Node Tiers  *(v2.0 — replaces "Two Sensor Node Types")*

The physical system has **six node tiers**, not two node types. The tiers differ in **what sensors they carry** and **where they are placed**, and both differences matter to the data.

Source of truth: the tier/sensor table image, plus `mesh-communication-mechanics.md` §2 for spacing.

### 2.1 The tier table

| Tier | Role | Sensors carried | Emitted channels |
|---|---|---|---|
| **1A Scout** | Baseline / flat zones | MPU-6050 6DoF (tilt + vibration) | `tilt_x`, `tilt_y`, `accel_{x,y,z}`, `gyro_{x,y,z}`, `vib_rms`, `vib_peak`, `vib_fdom`, `die_temp` |
| **1B Scout** | Tension / shear zones | MPU-6050 + 10 kΩ slide fissure meter + foil strain gauge | 1A's set **+** `fissure_mm`, `strain_ue` |
| **1C Scout** | Fault / water zones | MPU-6050 + capacitive soil moisture + wire extensometer | 1A's set **+** `moisture_pct`, `ext_delta_mm` |
| **2A Anchor** | Standard mesh router | ADXL355 ultra-high-precision inclinometer | `tilt_x`, `tilt_y`, `die_temp` |
| **2B Anchor** | Geotech borehole | Deep borehole piezometer + inclinometer string | `pore_pressure_kpa`, `borehole_tilt_d1..d4`, `die_temp` |
| **3 Gateway** | Master sink / edge AI | GPS/RTK absolute positioning | `gps_dx`, `gps_dy`, `gps_dz`, `die_temp` |

### 2.2 Placement density — geotechnical, not radio

Spacing is set by **the geology**, not by radio range. Straight from `mesh-communication-mechanics.md` §2:

- **Tier 1 Scouts: 15–25 m apart.** Ground failure is highly localised — a 2 m crack can open and a sensor 50 m away feels nothing. 1B sits on the high-tension shear edges; 1A maps the flat interior of the subsidence bowl; 1C follows the fault/water corridor.
- **Tier 2 Anchors: 100–150 m apart.** They reconstruct the macro-shape of the bowl and act as cluster heads. Sparse is sufficient because the bowl's large-scale shape does not vary sharply.
- **Tier 3 Gateway: 500–1000 m+ outside the angle of draw**, on immovable bedrock. **By construction it cannot move**, which is precisely what makes it the network's stable reference: any movement it reports is instrument drift, not ground movement.

### 2.3 Why the ADXL355 exists as its own tier

Tier 2A carries a precision inclinometer rather than the consumer MEMS part. It is roughly **40× quieter in tilt** than the MPU-6050. That is the entire engineering justification for 2A being a distinct tier, and the simulation must reproduce the noise gap — otherwise the tier is pointless in the data.

### 2.4 Cadence

**Every tier reports once per 60-second TDMA superframe** (`mesh-communication-mechanics.md` §5). So a mine's dataset has one synchronised global timestep grid, with all tiers aligned on it.

### 2.5 ⚠️ The geophone is gone

v1.0 specified a geophone node with a raw 1 kHz waveform and a 7-feature DSP vector. **There is no geophone in the final hardware.** That entire sensor, and both of its outputs, are removed.

**What replaces it:** the MPU-6050 already on every Tier 1 node is sampled as a short high-rate burst once per superframe and reduced on-node to three numbers — `vib_rms`, `vib_peak`, `vib_fdom`. This is what the image's "Tilt/Vibration: MPU-6050" line actually describes, and it preserves v1.0's real intent: **hear the rock cracking.**

The discriminator survives intact, because the four vibration sources sit in four separable frequency neighbourhoods:

| Source | `vib_fdom` | Meaning |
|---|---|---|
| Truck | 8–20 Hz | heavy vehicle — ignore |
| Conveyor | 50 ± 0.5 Hz | narrow-band machinery line — notch out |
| Blast | 40–80 Hz | check the blast register — veto if logged |
| **Microseismic** | **100–250 Hz** | **rock actually cracking — this one counts** |

Microseismic event rate scales with local strain, so shaking genuinely increases as the ground approaches failure rather than being painted on afterwards.

## 3. Multi-Mine Generation Requirement

### 3.1 Why multiple mines are required
A single simulated mine would cause the GNN to memorize one fixed graph topology instead of learning a general function of node position, local sensor readings, and neighborhood structure. Since real deployments will have different terrain and different node layouts every time, the training data must span many different mine topologies so the model generalizes.

### 3.2 How many mines

> **v2.0 locked parameters.** Each mine simulates a horizon of **2–14 days** at
> the 60 s cadence (2,880–20,160 timesteps), over a mine extent ranging from
> **400×200 m to 1200×1000 m**. At these settings a mine is 70k–1.6M rows, so
> full 60-second resolution is retained with no downsampling.

Generate mines from a **parametrized generator** (Section 3.3) so that mine count is a tunable, resumable batch process, not a fixed one-time target. Concretely:
- Build the generator so it can produce **one mine at a time** from a random seed plus parameter ranges.
- Start with a small pilot batch of **100–500 mines** first, and validate the full pipeline (generation → node placement → sensor simulation → labeling → file output) end-to-end on this pilot batch before scaling up.
- After the pilot batch is validated, scale to a target of **1,000–5,000 mines**, budget and runtime permitting. The exact final count is a compute/time tradeoff, not a fixed hard requirement — prioritize **diversity** of generated mines (varied terrain, geometry, and node layouts) over raw count. 5,000 near-identical mines are worth less than 1,000 diverse ones.

### 3.3 What must vary between mines
Each simulated mine must independently randomize (within reasonable, documented ranges you choose and record — see Section 7):
- Terrain / tunnel geometry (layout, depth, size of voids/tunnels).
- Subsurface stress/strain field parameters (see Section 4.1).
- Number and irregular placement of nodes **of every tier** (node positions must NOT be placed on a regular/uniform grid — placement should reflect irregular, terrain-appropriate positions, since real deployments cannot guarantee grid placement).
- Whether a collapse event occurs at all within the simulated time horizon for that mine (some mines should simulate stable ground with no collapse — see Section 5.2 on censoring). **v2.0: each mine draws its own collapse probability from Beta(3, 2) and then flips it, rather than sharing one fixed rate.** Mean 0.60, so stable mines stay plentiful, but propensity genuinely varies mine to mine — real sites are not equally failure-prone. The drawn value is recorded per mine.
- Timing and location of any collapse event(s), if they occur.

## 4. Per-Mine Simulation Contents

For each simulated mine, generate the following, in this order of dependency:

### 4.1 Latent Ground-Truth State (internal to the simulation, not sensor data)
This is the "hidden" physical reality that the sensors only partially observe. It does not need to be geologically rigorous, but it must exist as an explicit, evolving model so that sensor readings and collapse events are derived consistently from the same underlying cause. At minimum, simulate:
- A subsurface stress/strain field that evolves over the simulated time horizon (e.g., a scalar or vector field over 3D space and time — the exact mathematical model is your choice, but it must move toward failure conditions in mines where a collapse occurs, and remain stable in mines where it does not).
- A defined **failure threshold** or condition in this field that, when crossed, triggers a collapse event.
- A **precursor window**: the amount of simulated time between when instability begins building in the field and when actual collapse occurs. This must vary between mines/events (drawn from a distribution, not a fixed constant) to reflect that real precursor timing is not fixed.

### 4.2 Mine Geometry and Node Placement
- 3D coordinate system for the mine (define units, e.g. meters, and a consistent origin convention).
- Full list of node positions: `(x, y, z)` for **every node of every tier** in this mine.
- Each node must be tagged with its **tier** (`1A`, `1B`, `1C`, `2A`, `2B`, `3`) and its role (`scout`, `anchor`, `gateway`).
- Node placement must be irregular per Section 3.3.

### 4.3 Tier 1 Scout Sensor Data (1A / 1B / 1C)

For every Tier 1 node, at every 60-second timestep, generate:

**Shared by all three scout tiers (the MPU-6050 set):**
- `tilt_x_urad`, `tilt_y_urad` — ground slope, **derived as the first derivative of the subsidence surface** (§4.1), in microradians.
- `accel_x_g`, `accel_y_g`, `accel_z_g` — accelerometer in **g**. Must reflect the gravity vector projected through the local tilt: a tilted board sees gravity leak into its x and y axes.
- `gyro_x_dps`, `gyro_y_dps`, `gyro_z_dps` — angular rate in **deg/s**. The ground tilts far too slowly to produce a measurable rotation rate, so what the gyro actually reports is **its own bias walking around**. Simulate this as a slow-varying bias (see §4.5) — this is realistic, and it is why §4.3 of v1.0 called out gyro drift specifically.
- `vib_rms_mm_s`, `vib_peak_mm_s`, `vib_fdom_hz` — the MPU-6050 vibration burst reduced on-node (see §2.5). Burst rate and sample count are fixed across all mines and recorded in the global notes.
- `die_temp_c` — internal die temperature. Slow diurnal variation. **This channel is mandatory**: it is what makes the temperature-dependent bias of §4.5 correctable downstream.

**Tier 1B additionally (tension / shear zones):**
- `strain_ue` — horizontal strain in microstrain, **derived as the second derivative of the subsidence surface**, scaled by the horizontal-displacement coefficient `B`.
- `fissure_mm` — crack opening across the slide meter's gauge length, **derived by integrating horizontal strain over that gauge length**. Not invented independently.

**Tier 1C additionally (fault / water zones):**
- `ext_delta_mm` — wire extensometer, the **exact 3-D distance change** between the node peg and an anchor peg 10 m away. It must use the vertical component too: differential settlement shortens the wire even at zero horizontal strain.
- `moisture_pct` — capacitive soil moisture, % volumetric water content. Baseline + rain events that decay away, **plus a rise near a collapse site as failure approaches.** Water ingress is a genuine precursor to ground failure, and the fault/water zone is exactly where 1C is deployed — so this channel carries real predictive signal rather than an unrelated weather trace.

**Ground-truth companions.** Store the clean, un-corrupted `truth_tilt_x`, `truth_tilt_y`, `truth_strain`, `truth_subsidence` alongside the noisy channels. These are the quantities the sensors are noisy proxies for, and they exist so the corruption chain can be validated against ground truth.

**Every row carries:** `node_id`, `tier`, node position `(x,y,z)` (in `nodes.parquet`), and `t_s`.

### 4.4 Tier 2 and Tier 3 Node Data  *(v2.0 — replaces "Geophone Node Sensor Data")*

> ⚠️ **The v1.0 geophone section is superseded and removed.** There is no geophone in the final hardware, so the raw 1 kHz waveform and the 7-feature DSP vector (RMS, peak, peak-to-peak, crest factor, zero-crossing rate, dominant frequency, band-energy ratios) are **not generated**. See §2.5 for what replaces them and why the underlying intent survives.

**Tier 2A — standard mesh router (ADXL355):**
- `tilt_x_urad`, `tilt_y_urad` — same derivation as Tier 1, but at **precision-part noise levels, roughly 40× quieter than the MPU-6050**. The simulation must reproduce this gap; without it, tier 2A is indistinguishable from tier 1A in the data and its existence is unjustified.
- `die_temp_c`.

**Tier 2B — geotech borehole:**
- `pore_pressure_kpa` — piezometer. Baseline pore pressure, rising as the failure zone loads up, and responding to rainfall.
- `borehole_tilt_d1_urad` … `borehole_tilt_d4_urad` — inclinometer string reading tilt at **four fixed depths below the collar**. Ground tilt attenuates with depth, because the subsidence bowl is a surface expression — deeper sensors see less. The depths are fixed across all mines and recorded in metadata.
- `die_temp_c`.

**Tier 3 — master sink / edge AI gateway:**
- `gps_dx_mm`, `gps_dy_mm`, `gps_dz_mm` — RTK absolute position change. The gateway sits **outside the angle of draw on bedrock, so by construction it must read zero movement forever.** Anything it reports is instrument drift. That is exactly what makes it the network's stable reference and a common-mode drift detector.
- `die_temp_c`.

**Channels a tier does not carry must be null**, never zero-filled. A zero is a measurement; a null is an absence, and the downstream model must be able to tell them apart.

### 4.5 Sensor Noise (apply to every tier)
Do not output clean/noiseless simulated signals — this will not transfer to real hardware. For **every channel on every tier**, add:
- White/Gaussian sensor noise, at a magnitude representative of that part's datasheet noise density — **low-cost MEMS levels for the MPU-6050, precision levels for the ADXL355**, and appropriate levels for the strain gauge, fissure meter, extensometer, moisture sensor and piezometer (document every magnitude in the metadata file — see Section 7).
- Slow bias drift (already specified for the gyroscope in Section 4.3; apply an analogous slow-drift bias to the accelerometer, inclinometer, strain, fissure, extensometer, moisture and piezometer baselines as well).
- Temperature-dependent bias shift: since `die_temp` is simulated, make IMU bias shift slightly as a function of the simulated temperature value, to mimic a real, well-documented MEMS behavior.

## 5. Labels (Required for Every Node, Every Timestep)

Do not generate a simple binary "will collapse" label. Generate the following instead, which together support a time-to-event / survival-analysis training approach:

### 5.1 Time-to-Collapse
For every node, at every timestep, compute the time remaining until the **relevant** collapse event for that node (if one occurs before the simulation horizon ends). "Relevant" means: the nearest collapse event in space that plausibly affects that node — do not simply use one global collapse time for every node in the mine if collapses are spatially localized.

### 5.2 Censoring Flag
For every node: a flag indicating whether a collapse was actually observed within the simulated time horizon for that node's relevant region, or whether the simulation horizon ended with no collapse observed (this is a **censored** observation in survival-analysis terms — it means "this node survived at least the full simulated duration," not "this node is guaranteed safe forever"). Some mines in the dataset must have no collapse at all (fully censored), to give the model negative/stable examples — do not simulate only mines that eventually collapse.

### 5.3 Spatial Relevance Weighting
Since collapse is spatially localized, a node far from an eventual collapse site should not carry as strong/confident a label as a node close to it. For every node, in mines where a collapse occurs, compute a **distance-based weighting** (you choose the exact decay function, e.g. inverse-distance or a Gaussian falloff from the collapse site — document your choice) that scales how strongly that node's time-to-collapse label should be weighted during model training. Store this weight as its own column; do not bake it silently into the time-to-collapse value itself.

### 5.4 Collapse Event Metadata (mine-level, not per-node)
For every mine, separately store a list of all collapse events that occurred (a mine could plausibly have zero, one, or more than one collapse event during the simulated horizon):
- Collapse location `(x, y, z)`
- Collapse timestamp
- Collapse severity/magnitude (define a scale, e.g. a unitless 0-1 or 0-10 severity score; document your choice)

## 6. Graph Structure Metadata (For the GNN)

Per mine, output the information needed to construct a graph over that mine's nodes:
- Full node list with `(x, y, z)` position and **tier** (`1A`/`1B`/`1C`/`2A`/`2B`/`3`) plus role, as already specified in Section 4.2.
- Do **not** predefine a fixed edge list in this dataset — edges will be constructed downstream (e.g., via k-nearest-neighbors or radius-based connectivity) by the model training code, since different edge-construction strategies may be experimented with later. Your job is to output complete, accurate node positions and types; edge construction is out of scope for this simulation.

## 7. Required Output Format and Documentation

### 7.1 File structure
Organize output so that one mine's complete data is self-contained and easy to locate. Recommended structure (adjust naming as convenient, but keep this organizing principle):

```
/mine_00001/
  metadata.json            <- every randomized parameter used (see 7.2)
  nodes.parquet            <- node_id, tier, node_type, x, y, z
  readings.parquet         <- every sensor channel, every node, every timestep
  labels.parquet           <- time_to_collapse_s, censored_flag, spatial_weight
  collapse_events.parquet  <- mine-level event list (location, time, severity)
/mine_00002/
  ...
```

> **v2.0: CSV → Parquet.** v1.0 specified CSV. At 60-second cadence a single
> mine is up to 1.6M rows and a 1,000-mine dataset is ~500M rows; CSV is
> impractical at that size. Parquet is columnar, typed, ~10× smaller with zstd,
> and preserves **null vs zero** — which matters, because a channel a tier does
> not carry must be null, not zero. The organizing principle is unchanged: one
> mine's complete data is self-contained in one folder.
>
> **`readings.parquet` is long-format**: one row per node per timestep, with a
> column per channel and nulls where a tier does not carry that channel.
>
> **There is no `geophone_raw/` directory.** The geophone does not exist (§2.5).

### 7.2 Metadata requirements (critical — do not skip)
For every mine, output a `metadata.json` (or equivalent) recording every randomized parameter value actually used to generate that mine: terrain/geometry parameters, stress-field parameters, failure threshold, precursor window length, noise magnitudes applied, random seed used, node counts by tier, the fault-corridor geometry, the borehole depths, and the placement spacings actually drawn. **Nothing about how a mine was generated should be implicit or undocumented** — anyone reading only the metadata file for a given mine should be able to understand exactly what was simulated and why the resulting sensor/label data looks the way it does.

### 7.3 Global documentation (one-time, not per-mine)
Separately from per-mine metadata, produce one global document (e.g. `GENERATION_NOTES.md`) recording:
- All units used (distance, acceleration, angular rate, time, frequency).
- All parameter *ranges* the generator samples from (not just the value used in one mine, but the full documented range/distribution each parameter is drawn from across the whole dataset).
- The exact noise model, corruption stage order, and magnitudes used for **every channel on every tier**.
- The fixed MPU-6050 vibration burst rate and sample count.
- The frequency band definitions used to classify `vib_fdom` (truck / conveyor / blast / microseismic).
- The severity scale definition used for collapse events.
- The distance-decay function used for spatial relevance weighting (Section 5.3).

## 8. Train / Validation / Test Split (Downstream Use — For Awareness)

This is how the generated data will be used once complete; it affects nothing about how you generate the data, but is included so the split requirement is understood:

**The split must be done at the whole-mine level, never at the node or timestep level.** All nodes and all timesteps from a given mine must go entirely into exactly one of train, validation, or test. Splitting randomly at the node or timestep level would leak information between train and test (since nodes from the same mine share the same underlying stress field), producing misleadingly good results that do not reflect real generalization. Recommend saving a top-level manifest file listing which mine IDs belong to which split, but this can be decided after generation — it does not change what each mine's folder must contain.
